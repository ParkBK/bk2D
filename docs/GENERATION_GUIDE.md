# 영상 생성 규칙 (툴보다 이게 더 중요함)

bk2d 는 후처리 툴입니다. 원본 영상이 아래 규칙을 어기면 후처리로 복구할 수 없습니다.
각 규칙 옆에 **어기면 생기는 문제**와 **툴이 잡아내는 지표**를 적어두었습니다.

## 1. 기준 포즈(Base Pose) 이미지 하나를 먼저 확정한다

- 캐릭터 일러스트 1장 = 모든 클립의 **시작 프레임**이자 **끝 프레임**.
- 이미지→영상 생성 시 *start frame* 으로 이 이미지를 넣고, 서비스가 *end frame* 지정을 지원하면 같은 이미지를 넣는다.
- 어기면: idle ↔ attack 전환 시 포즈가 순간이동한다. → 지표 `startToBase`, `endToBase`
- end frame 지정을 지원하지 않는 모델이면, 액션 클립은 "기준 포즈로 돌아오는" 프롬프트를 쓰고 `endToBase` 로 걸러낸다. 통과율이 낮으면 이 방식 자체가 그 액션에 안 맞는 것.

## 2. 단색 크로마 배경

- 기준 포즈 이미지 자체를 **순수 초록(#00FF00 근처) 단색 배경**으로 만든다. 그림자·바닥·그라데이션 금지.
- 캐릭터에 초록 계열 색을 쓰면 안 된다. 초록 캐릭터라면 파랑(#0000FF) 배경 + `"color": "#0000ff"`.
- 프롬프트에 `solid green background, no shadow, no floor, static background` 류를 명시.
- 어기면: 외곽이 뜯기거나 몸 일부가 투명해진다. rembg 모드로 대체 가능하지만 프레임마다 마스크가 흔들린다.

## 3. 카메라 완전 고정

- `static camera, locked-off shot, no zoom, no pan` 명시. 카메라 무브 프리셋 사용 금지.
- 툴은 클립별로 **첫 프레임 기준 1회** 스케일/위치를 맞춘다. 클립 *내부*의 카메라 이동은 보정하지 않는다
  (점프 같은 실제 동작과 카메라 이동을 구분할 수 없기 때문).
- 어기면: 캐릭터가 셀 안에서 미끄러지거나 커졌다 작아진다.

## 4. 전신이 프레임 안에

- 발끝·무기 끝이 화면 밖으로 잘리면 잘린 그대로 스프라이트가 된다.
- 기준 포즈 이미지에 캐릭터 주변 여백을 충분히(특히 공격 방향) 둔다.

## 5. idle 루프

- 길게(5초+) 뽑고 툴이 첫 프레임과 가장 비슷한 지점을 찾아 자른다. → 지표 `loopSeam`
- 숨쉬기·머리카락 흔들림 정도의 작은 동작이 잘 된다. 큰 동작일수록 이음매가 보인다.

## 6. 해상도 / fps 예산

| 항목 | 권장 | 이유 |
|---|---|---|
| 캐릭터 높이(`height`) | 256~512px | 1024px 이상은 메모리 폭증 |
| fps | 8~12 | 2D 애니 느낌 + 프레임 수 절감 |
| 클립 길이 | 액션 0.5~1.5초 | 생성 영상 5초 중 필요한 구간만 써야 함 |

메모리 감각: 셀 300x400, 12fps, 1초 액션 = 12프레임 ≈ RGBA 비압축 5.8MB, ASTC 6x6 압축 시 ≈ 0.6MB.
액션 10개 × 캐릭터 20명이면 압축 기준으로도 100MB+ — 모바일이면 이 숫자를 먼저 계산해볼 것.

## 7. 이 방식이 안 맞는 경우 (Spine 이 여전히 나은 경우)

- 장비/코스튬 교체가 있는 캐릭터 (조합마다 재생성 필요)
- 액션 간 블렌딩, 시선 추적, IK 가 필요한 경우
- 같은 캐릭터의 액션 수가 많고 디자인 일관성이 중요한 경우 (생성할 때마다 디테일이 조금씩 변함)
